# Day 21 - 接下来做什么？

* [课程视频](https://youtu.be/MW9q6NWNDyM)

这是什么迷惑操作——这课程不是说好只有 20 天吗？

是的，但希望你还会继续学习，所以这里有一些你可能感兴趣的方向建议。

## 折腾你的服务器

你对课程中用的那台服务器已经很熟悉了，那就继续用它。也许卸载 Apache2，装上 NGINX，一个竞争性的 Web 服务器。持续统计 ssh 的“攻击者”。随便什么。一台免费的 AWS 能用一年，而一台 5 美元/月的服务器应该是你很容易就能说服自己买下的。

## 添加你会用到的服务

你现在应该有能力和着教程安装并运行你自己的 Minecraft、Wordpress、WireGuard VPN 或 Mediawiki 实例了。预期会遇到一些问题——这都是很好的经验！

去 [Server World](https://www.server-world.info/en/note?os=Ubuntu_22.04&p=httpd&f=1) 找些灵感。

## 扩展你的学习

别再浏览关于 Gnome、KDE 或 i3 的文章了——开始看看像“*每个系统管理员都应该知道的 20 个 Linux 命令*”这样的文章。把它们都试一遍，钻研各种选项。就像学习外语词汇一样，只有认识这些“单词”，你才能用得上它们！

如果你还没看过，去看看 [Linux Journey](https://linuxjourney.com/)，特别是如果你对 Linux 还相当陌生、想看看另一种学习方式的话。[Linux 101 Hacks](https://linux.101hacks.com/toc/) 也是一个不错的资源。

在 [SadServers.com](https://sadservers.com/) 上用一些挑战来练习你学到的东西。在那里你会找到一系列场景，你必须在 Linux 服务器上做一些事情、修一些东西或者“黑”一些东西。这是在不折腾自己服务器的前提下锻炼故障排查技能的好办法。

想在命令行上快到飞起，试试 [Command Line Challenge](https://cmdchallenge.com/)、[practicelinux.com](https://www.practicelinux.com/home)、[learnshell.org](https://www.learnshell.org/) 和 [commandlinefu.com](https://www.commandlinefu.com/commands/browse)。

如果你下一阶段的目标是进入 DevOps，看看 [DevOps 路线图](https://roadmap.sh/devops)。

## 认证

如果你打算专业地从事 Linux 工作，而且手上还没有一份亮眼的履历或简历，那么你应该瞄准拿一个 Linux 认证。真正算数的其实只有三个认证/路线：

* [CompTIA Linux+](https://www.comptia.org/certifications/linux)——一次考完，与发行版无关，但在市场上价值不高。如果你不想在 Linux 上钻得太深，或者你还有其他 CompTIA 路线在进行中、而且雇主会为它们付费，那就考这个。
* [LPI LPIC-1: Linux Administrator](https://wiki.lpi.org/wiki/Main_Page)——对他们的各种认证/课程覆盖范围有非常详尽的描述。这些考试可以考得很深，涵盖你能想到的纯 Linux 的一切。在雇主那里不那么受欢迎，但知识当然是有价值的。
* [Red Hat](https://www.redhat.com/en/services/all-certifications-exams)——你可能会在这里花很多时间和金钱，但它很可能物有所值！它面向 Red Hat Enterprise Linux 发行版及其特性，是实操考试（其他的是多选题），在企业圈子里广为人知，确实常常出现在简历上。

即使你不想/不需要认证，这些参考材料中的主题大纲也能很好地提示你自学时该重点关注哪些领域。
