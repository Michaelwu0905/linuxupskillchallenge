# Day 13 - 用户与组

* [课程视频](https://youtu.be/mBcExazxLU8)

## 简介

今天你要在系统上设置另一个用户。你要想象这是一个你信任的服务台人员，你只让他做几件简单的事：

* 检查系统是否在运行
* 用 `df -h` 检查磁盘空间

……但你也希望他能重启系统，因为你相信“关机再开机”能解决大部分问题 :-)

你会涉及好几个新领域，玩得开心！

## 今天的任务

* 创建一个新用户
* 创建一个新组
* 创建一个新用户并加入已有的组
* 让新用户成为 sudoer

跟着[这个演示](https://asciinema.org/a/631680)做。

## 添加新用户
给你的新用户选一个名字——例子中我们用 “helen”，所以要添加这个新用户：

`sudo adduser helen`

（Linux 中名字区分大小写，所以 “Helen” 会是一个完全不同的用户）

“adduser” 命令在每个发行版中的行为略有不同——如果它没有要你为新用户设置密码，那就现在手动设置：

`sudo passwd helen`

现在你会在简单的文本用户数据库 `/etc/passwd` 中看到一条新记录（用 `less` 看看它），并在文件 `/etc/group` 中看到同名的组。用户密码的哈希值在 `/etc/shadow` 中（如果你用 “sudo”，这个文件你也能读——检查一下权限看看它们是怎么设置的。出于显而易见的原因，它不是所有人都能读的）。

如果你习惯了其他操作系统，可能很难相信，但这些简单的文本文件就是整个 Linux 用户数据库，你甚至可以通过直接编辑这些文件来创建用户和组——尽管一般不建议这么做。

此外，`adduser` 还会创建一个主目录，例如 `/home/helen`，并带有正确的权限。

**注意！** `useradd` 和 `adduser` 不是一回事。它们都创建一个新用户，但行为差异很大。查看“扩展”部分中的链接了解这些差异。

## 添加新组

假设我们希望我组织里的所有开发者都有自己的组，这样他们就能访问相同的东西。

`sudo groupadd developers`

在大多数现代 Linux 系统上，每个用户都会有一个对应的组，所以用户 “ubuntu” 是组 “ubuntu” 的成员。但如果你愿意，也可以用 `ingroup` 标志直接把一个新用户创建进一个已有的组。那么新用户 `fred` 会这样创建：

`sudo adduser --ingroup developers fred`

## 把用户加入组

用户也可以是多个组的成员，并且可以按需加入组。

要看你属于哪些组，直接输入：`groups`

在 Ubuntu 系统上，第一个创建的用户（在你的情况下是 `ubuntu`）应该是这些组的成员：`ubuntu`、`sudo` 和 `admin`——如果你列出 `/var/log` 文件夹，你会看到正是因为你是 `sudo` 组的成员，你才能用 `less` 读取和查看 `/var/log/auth.log` 的内容。

“root” 用户可以用下面的命令把一个用户加入已有的组：

`usermod -a -G group user`

所以你的 `ubuntu` 用户只要在命令前加上 `sudo` 就能做同样的事。

由于新用户 `helen` 不是系统中创建的第一个用户，她没有运行 `sudo` 的权力——而*你的*用户因为属于 `sudo` 组所以有这个权力。

那么，要检查 `helen` 是哪些组的成员，你可以像这样“变成 helen”来切换用户：

`sudo su helen`

然后：

`groups`

如果你尝试做只有 sudo 用户才能做的事，比如读取 `/var/log/auth.log` 的内容，即使加 `sudo` 前缀也不会成功。Helen 不是 sudo 用户，没有执行这个操作的权限。

现在输入 “exit” 回到你的普通用户，然后你可以用下面的命令把 `helen` 加入这个组：

`sudo usermod -a -G sudo helen`

这次不用再切换用户，直接运行 `groups helen` 来检查即可。对 `fred` 也试试，看看一切是如何运作的。

看看你的新用户是否能用 `sudo reboot`。

## 聪明的 SUDO 技巧

你的新用户只是普通用户，所以在我们设置之前无法用 `sudo` 以提升的权限运行命令。我们可以简单地把它加进一个预定义的、能以 root 身份用 sudo 做*任何事*的组（就像我们对 `helen` 做的那样）——但我们不想给 `fred` 那么大的权力。

用 `ls -l` 查看文件 `/etc/sudoers` 的权限。魔法就定义在这里，你会看到它被严格管控，但你应该可以用 `sudo less /etc/sudoers` 查看它。你想在里面为你的新用户添加一条新记录，为此你需要运行一个特殊工具：`visudo`

要运行它，你可以通过下面的命令临时“变成 root”：

`sudo -i`

注意你的提示符变成了 `#`

现在直接运行 `visudo` 开始编辑 `/etc/sudoers`——通常它会用 `nano`。

`/etc/sudoers` 中所有以 “#” 开头的行都是可选注释。你会想加上类似这样的行：

	# Allow user "fred" to run "sudo reboot"
	# ...and don't prompt for a password
	#
	fred ALL = NOPASSWD:/sbin/reboot

你可以把这些行加在任何看起来合理的地方。`visudo` 命令会自动检查你的语法，如果有错误就不允许保存——因为一个损坏的 sudoers 文件可能把你锁在服务器外面！

输入 `exit` 摘掉你的魔法帽、变回普通用户——注意你的提示符恢复成 `$`。

## 测试

以你的测试用户登录并输入 `sudo reboot` 来测试。
注意你可以通过下面的方式“变成” helen：

`sudo su helen`

如果你的 ssh 配置只允许用公钥登录，你就需要设置 `/home/helen/.ssh/authorized_keys`——包括把属主和权限设置正确。这是对你在这个领域理解程度的一个小挑战！
