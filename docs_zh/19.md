Linux 支持大量不同的“文件系统”——虽然在服务器上你通常只会跟 _ext3_ 或 _ext4_ 打交道，也许还有 _btrfs_——但今天我们不处理其中任何一个；而是处理位于它们_之上_的那一层 Linux——Linux 虚拟文件系统（VFS）。

VFS 是 Linux 的关键部分，对它以及一些相关概念有个总体了解，对自信地管理系统非常有用。

## 再下一层

Linux 在文件名和文件在磁盘上的实际数据之间还有额外的一层——这就是 _inode_（索引节点）。它有一个数值，你最容易通过两种方式看到：

`ls` 命令上的 `-i` 开关：

     ls -li /etc/hosts
     35356766 -rw------- 1 root root 260 Nov 25 04:59 /etc/hosts

`stat` 命令：

     stat /etc/hosts
     File: `/etc/hosts'
     Size: 260           Blocks: 8           IO Block: 4096   regular file
     Device: 2ch/44d     Inode: 35356766     Links: 1
     Access: (0600/-rw-------)  Uid: (  0/   root)   Gid: (	0/	root)
     Access: 2012-11-28 13:09:10.000000000 +0400
     Modify: 2012-11-25 04:59:55.000000000 +0400
     Change: 2012-11-25 04:59:55.000000000 +0400

每个文件名都“指向”一个 inode，而 inode 又指向磁盘上的实际数据。这意味着多个文件名可以指向同一个 inode——因而内容完全相同。事实上这是一种标准技术——叫做“硬链接”。另一个要注意的重要点是：当我们查看文件名的权限、所有权和日期时，这些属性实际上是保存在 inode 层面的，而_不是_文件名层面的。很多时候这种区分只是理论上的，但它可能非常重要。

## 两种链接

按下面的步骤做一遍，熟悉硬链接和软链接：

首先用下面的命令移动到你的主目录：

`cd`

然后用 `ln`（“link”）命令创建一个“硬链接”，像这样：

`ln /etc/passwd link1`

再用下面的方式创建一个“符号链接”（也叫 “symlink”）：

`ln -s /etc/passwd link2`

现在用 `ls -li` 查看生成的文件，并用 `less` 或 `cat` 查看它们。

注意符号链接的权限一般显示为允许一切——但真正重要的是它所指向的那个文件的权限。

硬链接和符号链接在 Linux 中都被广泛使用，但符号链接尤其常见——例如：

`ls -ltr /etc/rc2.d/*`

这个目录保存着当你的机器切换到“运行级别 2”（它正常的运行状态）时启动的所有脚本——但你会看到事实上它们大多数都是指向 _/etc/init.d_ 中真实脚本的符号链接。

像下面这样的情况也非常常见：

     prog
     prog-v3
     prog-v4

其中程序 “prog” 是一个符号链接——原本指向 v3，但现在指向 v4（如有需要也可以指回去）。

读读提供的资源，并在你的服务器上测试，以便更好地理解。特别要看看权限和文件大小在符号链接、硬链接和普通文件之间是如何表现的。

## 区别

硬链接：

* 只能链接到文件，不能链接到目录
* 不能引用不同磁盘/卷上的文件
* 即使文件被移动，链接仍然会引用它
* 链接引用的是磁盘上的 inode/物理位置

符号（软）链接：

* 可以链接到目录
* 可以引用不同硬盘/卷上的文件/文件夹
* 原文件被删除后链接依然存在
* 如果文件被移动，链接就_不再_引用它
* 链接引用的是抽象的文件名/目录，而_不是_物理位置。
* 它们有自己的 inode
