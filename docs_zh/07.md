# Day 7 - 服务器及其服务

* [课程视频](https://youtu.be/VzXwO0qq-bg)
* 配套视频：[Apache 与系统服务](https://www.youtube.com/live/WtcX60n-ui0?t=9150s)

## 简介

今天你会安装一个常见的服务器应用——Apache2 Web 服务器——也叫 *httpd*，即 “Hyper Text Transport Protocol Daemon”（超文本传输协议守护进程）！

如果你是网站方面的专业人士，你的做法可能略有不同，但我们关注的重点不是 Apache 本身，也不是网站内容，而是要更好地理解：

* 应用安装
* 配置文件
* 服务
* 日志

## 今天的任务

* 安装并运行 apache，把你的服务器变成一台 _Web 服务器_

## 说明

* 用 `sudo apt update` 刷新可用软件包（应用）列表——这需要一两分钟，但能确保你拿到最新版本。
* 用一条简单的命令从仓库安装 Apache：`sudo apt install apache2`
* 在浏览器中访问 _http://[你服务器的外部 IP]_ 来确认它正在运行——你应该会看到一个确认页面。
* Apache 是作为“服务”安装的——一种随服务器启动而自动启动、并且无论有没有人登录都持续运行的程序。试着用命令停止它：`sudo systemctl stop apache2`——确认网页已经打不开了——然后用 `sudo systemctl start apache2` 重新启动它——并用 `systemctl status apache2` 检查它的状态。
* 和绝大多数 Linux 软件一样，配置由 _/etc_ 目录下的文件控制——查看 `/etc/apache2` 下的配置文件，尤其是 `/etc/apache2/apache2.conf`——你可以直接用 `less` 查看它们，或者用 `vim` 编辑器按需查看和编辑。
* 在 `/etc/apache2/apache2.conf` 中有一行文字：“IncludeOptional conf-enabled/\*.conf”。这告诉 Apache，子目录 *conf-enabled* 中的 \*.conf 文件应该在加载时与 `/etc/apache2/apache2.conf` 中的配置合并。这种用大量小的特定配置文件的方式很常见。
* 如果你熟悉 Web 服务器的配置，那就尽情折腾吧：设置一些虚拟主机，或者加一些模块等等。
* 默认网页的位置由文件 `/etc/apache2/sites-enabled/000-default.conf` 中的 *DocumentRoot* 参数定义。
* 用 `less` 或 `vim` 查看默认页面的代码——通常在 `/var/www/html/index.html`。它使用了相当复杂的现代网页设计——所以在你的 ssh 会话里执行 `sudo vim /var/www/html/index.html`，先删掉已有内容（用你昨天学到的 vim 技巧），然后用更简单的代码替换它。你甚至可以直接放纯文本在那里，它也能工作，显示简单文本并不强制要加 HTML 标签。不过你也可以去浏览我们的示例服务器 [http://142.93.60.184/](http://142.93.60.184/) 并使用我们的示例代码。再次用你工作站的浏览器访问 _http://[你服务器的外部 IP]_ 查看结果。
* 和大多数 Linux 服务一样，Apache 把日志保存在 `/var/log` 目录下——看看 `/var/log/apache2` 里的日志——在 `access.log` 文件中，你应该能看到你浏览测试页面时的那次会话。注意细节多到铺天盖地——这很正常，不过在后面的一课中你会学到如何只筛选出你想要的内容。也注意一下 `error.log` 文件——希望它是空的！

## 分享你的进展

练习你的文本编辑技能，也让你“同学们”来评判你的进展：用 `vim` 编辑 `/var/www/html/index.html`，然后把访问它的 URL 发到论坛上。（它不必好看！）

## 安全

* 作为这台服务器的系统管理员，你要为它的安全负责，你需要非常清楚：你现在已经增大了服务器的“攻击面”。除了 22 端口上的 *ssh* 之外，你现在还把 *apache2* 的代码暴露在 80 端口上。随着时间推移，日志可能会显示来自各种访问型搜索引擎和攻击者的访问——这完全正常。
* 如果你运行这些命令：`sudo apt update`，然后 `sudo apt upgrade`，并接受建议的升级，那么你就会拥有所有最新的安全更新，对于测试环境来说足够安全了——但你应该定期重新运行它。
