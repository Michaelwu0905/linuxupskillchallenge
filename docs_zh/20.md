## 简介

今天是本课程的最后一节。如果你把所有课都坚持做下来了，给自己鼓鼓掌！

你已经看到，系统管理员一个持续被强调的重点就是尽可能自动化，也看到了 Linux 系统是多么“透明”——只要你知道该去哪里看！

在今天这最后一节课里，我们会讲讲如何编写小程序，也就是“shell 脚本”，来帮助管理你的系统。

在 Linux 命令行上输入时，你是在与“命令解释器”直接交流，它也叫“shell”。通常这个 shell 是 _bash_，所以当你把命令串起来做成一个脚本时，其结果可以叫 “shell 脚本”，或者 “bash 脚本”。

为什么要做脚本，而不是直接手动输入命令呢？

* 省打字。还记得我们用一长串 `grep`、`cut` 和 `sort` 命令搜索日志的时候吗？如果需要做这类事情超过几次，把它变成脚本就能省下打字的功夫——还有打错的功夫！
* 参数。一个脚本可以根据你提供的参数做几件不同的事。
* 自动化。把你的脚本放进 _/etc/cron.daily_，它就会每天运行；或者在合适的 _/etc/rc.d_ 文件夹里放一个指向它的符号链接，你就能让它在系统每次关机或启动时运行。

## 今天的任务

* 写一个短脚本，列出尝试登录你服务器的前 3 个 IP 地址

## 从 SHEBANG 开始！

脚本就是简单的文本文件，但如果你给它们设置了“执行”权限，系统就会去找一行特殊的、以 “#” 和 “!” 两个字符开头的行——也就是文件顶部的 “shebang”（也叫 “crunchbang”）。

这一行通常长这样：

     #!/bin/bash

通常以 “#” 字符开头的任何内容都会被当作注释，但在第一行且后面跟着 “!” 时，它会被解释为：_“请把剩下的内容喂给 /bin/bash 程序，它会把其作为脚本解释执行”_。我们所有的脚本都会用 _bash_ 语言编写——和你在整个课程中在命令行上敲的一样——但脚本也可以用许多其他“脚本语言”编写，所以一个 Perl 语言的脚本可能以 `#!/usr/bin/perl` 开头，一个 Python 脚本则以 `#!/usr/bin/env python3` 开头。

## 你的第一个脚本

你要写一个小脚本，用 _/var/log/auth.log_ 中的条目列出最近尝试登录你服务器失败最多的那些人。

用 `vim` 在你的主目录里创建一个文件 `attacker`，内容如下：

     #!/bin/bash
     #
     #   attacker - prints out the last failed login attempt
     #
     echo "The last failed login attempt came from IP address:"
     grep -i "disconnected from" /var/log/auth.log|tail -1| cut -d: -f4| cut -f7 -d" "

像这样在脚本顶部写注释并不是严格必需的（计算机会忽略它们），但这是一个值得养成的良好职业习惯。

要让它可执行，输入：

`chmod +x attacker`

现在要运行这个脚本，你只需按名字引用它——但当前目录（有意地）不在你的 $PATH 里，所以你需要用下面两种方式之一：

     /home/support/attacker
     ./attacker

一旦你对一个脚本满意了，并想让它随手可用，你可能会想把它移到 $PATH 中的某个位置——而 _/usr/local/bin_ 通常就是合适的地方，所以试试这个：

`sudo mv attacker /usr/local/bin/attacker`

……现在只要你输入 `attacker`，它就能直接工作了。

## 扩展这个脚本

你可以扩展这个脚本，让它需要一个参数，并在你没给参数时打印一些语法帮助。这里面有几个新技巧，值得研究：

```
#!/usr/bin/env bash
#
#   topattack - list the most persistent attackers
#
# Ensure "graceful exit" in case the script was sourced.
if [[ ${BASH_SOURCE[0]} != "$0" ]]; then
        echo "Don't source this file. Execute it.";
        return 1;
fi;
# Display usage hint if the script was executed with no/invalid argument.
if [[ -z "$1" ]] || [[ ! "$1" =~ ^[0-9]+$ ]] || (( $1 < 1 )); then
        echo -e "\nUsage:\n\t$(basename "${BASH_SOURCE:-$0}") <NUM>";
        echo "Lists the top <NUM> attackers by their IP address.";
        echo -e "(<NUM> can only be a natural number)\n";
        exit 0;
fi;
# Make sure the log file is available for parsing by this user.
if [[ ! -f "/var/log/auth.log" ]] || [[ ! -r "/var/log/auth.log" ]]; then
        echo -e "\nI could not read the log file: '/var/log/auth.log'\n";
        exit 2;
fi;
# Use 'cat' command and "here document" to avoid repeated 'echo' commands.
cat << _EndOfHeader_

Top $1 persistent recent attackers

Attempts      IP
-----------------------
_EndOfHeader_
# Too long command pipelines can be spanned over multiple lines with \
# followed immediately by a newline character (i.e. ENTER, RETURN, '\n')
grep 'Disconnected from authenticating user root' "/var/log/auth.log" \
 | cut -d':' -f 4 | cut -d' ' -f 7 | sort | uniq -c | sort -nr | head -n "$1";
```

同样，用 vim 创建 `"topattack"`，用 `chmod` 让它可执行，等它正确工作后再用 `mv` 把它移进 _/usr/local/bin_。

（顺便说一句，你可以用 `whois` 查找这些 IP 中任何一个的详细信息——只要意识到那个“正在攻击”你的系统可能也是一个被黑进去的无辜一方。）

像这样收集一些简单的脚本，是你可以轻松做到的事情，能让你的系统管理任务更简单、更快、更不容易出错。

如果自动化并把日常任务脚本化听起来像是你真心喜欢做的事，你也许还想把机器和服务的搭建过程也脚本化。尽管你可以像本课展示的那样用 bash 脚本来完成，但选择 ansible、cloudinit 或 terraform 这类编排框架也有一些好处。这些框架超出了本课程的范围，但可能值得一读。
