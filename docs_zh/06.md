## 简介

简单的文本文件是 Linux 的核心，所以编辑它们是关键的系统管理员技能。有一系列面向初学者的简单文本编辑器。你会看到的比较常见的例子有 `nano` 和 `pico`。它们看起来像是 20 世纪 80 年代为 DOS 写的——但相当容易“自己摸索明白”。

然而，真正的系统管理员<sup>tm</sup>用的是 `vi`——这是那个总是默认安装的编辑器——今天你就来开始使用它。

Bill Joy 在 1970 年代中期写了 Vi——就连我们要重点讲的“现代版” _Vim_ 也已经 20 多岁了，但尽管年代久远，它们仍然是命令行服务器上的标准编辑器。此外，它们在程序员、甚至一些作家中都有忠实的追随者。Vim 实际上是 [Vi IMproved](https://vimhelp.org/intro.txt.html) 的缩写，是 Vi 的直系后裔。

很多时候你输入 `vi`，系统实际启动的其实是 `vim`。要看看你的系统是不是这样，运行：

```bash
vi --version
```

如果 `vi` 命令实际上[符号链接](19.md#两种链接)到了 `vim`，你应该会看到类似下面的输出：

```bash
user@testbox:~$ vi --version
VIM - Vi IMproved 8.2 (2019 Dec 12, compiled Oct 01 2021 01:51:08)
Included patches: 1-2434
Extra patches: 8.2.3402, 8.2.3403, 8.2.3409, 8.2.3428
Modified by team+vim@tracker.debian.org
Compiled by team+vim@tracker.debian.org
...
```

### 如果我没有安装 VIM 怎么办？

本课后续内容假定你的系统上安装了 `vim`，它通常默认就是安装好的。但在某些情况下并非如此，如果你尝试运行下面的 `vim` 命令，可能会看到类似下面的错误：

```bash
user@testbox:~$ vim
-bash: vim: command not found
```

#### 方案 1 - 给 VIM 设置别名

一个办法是直接把下面[说明](#说明)中所有 `vim` 命令都替换成 `vi`。Vim 与 Vi 反向兼容，下面所有练习对 Vi 和 Vim 都应该同样有效。为了让事情更省事，我们可以直接给 `vim` 命令起个别名，让它实际运行 `vi`：

```bash
echo "alias vim='vi'" >> ~/.bashrc
source ~/.bashrc
```

#### 方案 2 - 安装 VIM

另一个办法——也是很多系统管理员大概会选的办法——如果 Vim 没装，就把它装上。

在 Ubuntu 上用系统[软件包管理器](15.md)安装 Vim，运行：

```bash
sudo apt install vim
```

> **注意：** 由于 Linux Upskill Challenge 推荐使用的 Linux 发行版是 [Ubuntu Server LTS](00-VPS-big.md#简介)，为其他各种 Linux“发行版”安装 Vim 超出了本课的范围。不过上面这条命令“应该”对大多数 Debian 系 Linux 系统都有效，所以如果你用的是 Mint、Debian、Pop!_OS 或者其他众多 Ubuntu 变体之一，不妨试一试。对于 Debian 系以外的 Linux 发行版，做几次简单的网络搜索大概就能帮你找到如何用其他 Linux 的软件包管理器安装 Vim。

## 你需要知道的两件事

* 有两种“模式”——行为差异极大
* 屏幕上几乎没有任何提示告诉你当前处在哪个模式！

这两种模式是“普通模式（normal mode）”和“插入模式（insert mode）”，作为初学者，只需记住：

`"按两次或更多次 Esc 回到普通模式"`

“普通模式”用于输入命令，“插入模式”用于书写文本——类似普通文本编辑器的默认行为。

## 说明

那么，先找一个文本文件来编辑。复制一份 `/etc/services` 就很合适：

```bash
cd
pwd
cp -v /etc/services testfile
vim testfile
```

此时文件已经显示在屏幕上，而我们处在“普通模式”。不过与 `nano` 不同，屏幕上没有菜单，任何东西如何运作都完全不明显！

先按一次或两次 _Esc_ 确保我们在普通模式（记住上面那个技巧），然后输入 `:q!` 并按 _Enter_。这会在不保存任何改动的情况下退出——当你还不知道自己在干什么时，这是*至关重要*的第一项技能！
现在我们再进去随便玩玩，看看 `vim` 有多强大、多危险——然后同样不保存退出：

```bash
vim testfile
```

用 _h_ _j_ _k_ 和 _l_ 键四处移动（这是传统的 `vi` 方式），然后试试用方向键——如果它们能用，那就随便用——但记住那些 _hjkl_ 键，因为有一天你可能在一个只有传统 `vi` 的系统上，而方向键不起作用。

现在随便在文件里移动玩玩。然后按前面说过的 _Esc_ _Esc_ `:q!` 退出。

既然你已经掌握了这些，我们来做点更进阶的。

```bash
vim testfile
```

这次，往下移动几行进入文件内部，按 _3_ 再按一次 _3_，然后按 _d_ 再按一次 _d_——突然文件里 33 行就被删掉了！

为什么？因为你在普通模式，而 _33dd_ 是一个表示“删除 33 行”的命令。现在，你仍在普通模式，所以按 _u_——你刚刚所做的改动就被神奇地撤销了。挺妙吧？

现在你知道了 `vim` 新手要掌握的三条基本技巧：

* _Esc_ _Esc_ 总能让你回到“普通模式”
* 在普通模式下 `:q!` 总能退出，且不保存你做过的任何改动，以及
* 在普通模式下 `u` 会撤销上一个操作

那么，下面是一些有用、有产出的操作：

* 查找内容：从普通模式输入 `G` 跳到文件末尾，然后 `gg` 回到顶部。我们来搜索一下对 “sun” 的引用，输入 `/sun` 找到第一个实例，按回车，然后反复按 _n_ 逐个走过后面所有的出现位置。现在回到文件顶部（记得用 _gg_），试着搜索 “_Apple_” 或 “_Microsoft_”。
* 剪切和粘贴：回到文件顶部（用 _gg_），看看开头几行注释（以 “#” 开头的那些）。试着剪掉其中一些，再粘贴回来。做法很简单：把光标定位在某一行上，然后（例如）输入 _11dd_ 删除 11 行，接着立刻按 _P_ 把它们粘回来——然后再往下移动一点，用 _P_ 把同样的 11 行粘贴到那里。
* 插入文本：移动到文件中的任意位置，按 _i_ 进入“插入模式”（屏幕底部可能会显示出来），然后开始输入——完成后用 _Esc_ _Esc_ 回到普通模式。
* 把你的改动写入磁盘：从普通模式输入 `:w` 表示“写入”但留在 `vim` 中，或者 `:wq` 表示“写入并退出”。

这就是你关于 `vim` 所*需要*学的全部了——但如果你有时间，还有多得多的东西你*可以*学。你的下一步应该是运行 `vimtutor`，走一遍“官方”的 Vim 教程。第一次通常需要大约 30 分钟。为了巩固你的 Vim 技能，养成连续 1–2 周每天过一遍 vimtutor 的习惯，你就应该能打下扎实的基础。

> **注意：** 如果你在上面那些练习中[把 vim 别名到了 vi](#方案-1-给-vim-设置别名)，那么现在可能是[安装 vim](#方案-2-安装-vim)的好时机，因为 `vimtutor` 命令是由它提供的。装好 Vim 后，你可以在 Vim 里运行 `:help vimtutor` 来查看帮助以及一些其他技巧/窍门。

不过，如果你认真想成为系统管理员，那么从现在起_坚持_用 `vim`（或 `vi`）做你所有的编辑工作就很重要。

最后一点，你可能会看到关于 [Vi 与 Emacs 之争](https://en.wikipedia.org/wiki/Editor_war)的引用。这是程序员之间长期存在的竞争，而不是系统管理员之间的——你需要学的是 `vi/vim`。

## 为什么我不能就一直用 NANO？

* 作为专业人士，在很多情况下你会在别人的系统上工作，而他们往往对稳定性非常偏执。你可能没有权限直接 “sudo apt install <你最喜欢的编辑器>”——即使技术上你能做到。

* 然而，`vi` 总是安装在任何 Unix 或 Linux 机器上，从微型 IoT 设备到超级计算机集群。事实上它是 Single Unix Specification 和 [POSIX](https://en.wikipedia.org/wiki/POSIX) 所要求的。

* 而且坦白说，它是 Linux 老手的一道[身份验证口令（shibboleth）](https://en.wikipedia.org/wiki/Shibboleth)。作为新手，在面试时说“我只是 vi/vim 的初学者”没问题——但说你讨厌它、永远记不住[怎么退出](https://github.com/hakluke/how-to-exit-vim)就非常冒险了。

所以，如果你的目标是专业地从事 Linux 工作，那这么做是合理的；但如果你只是在自己的系统上折腾，那就尽管选 `nano` 或 `pico` 等等吧。
