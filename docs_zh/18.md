## 简介

当你在管理一台远程服务器时，日志是你最好的朋友，但磁盘空间问题可能是你最坏的敌人——所以，尽管 Linux 应用通常非常擅长生成日志，它们也需要被管控。

`logrotate` 应用让你的日志保持受控。用它你可以定义想保留多少天的日志；把它们切分成易于管理的文件；压缩它们以节省空间，甚至把它们保存在一台完全独立的服务器上。

优秀的系统管理员热爱自动化——让计算机自动去做那些无聊重复的事情，就是说得通。

## 今天的任务

* 检查 _apache2_ 中严重级别（Severity）为 3 的日志
* 编辑 _apache2_ 的 logrotate 配置，让它每天轮转

## 你的日志在轮转吗？

看看你的日志目录——_/var/log_，以及像 _/var/log/apache2_ 这样的子目录。你能看出你的日志已经在轮转了吗？你应该会看到一个 _/var/log/syslog_ 文件，同时还有一系列更旧的压缩版本，名字像 _/var/log/syslog.1.gz_。

## 它们什么时候轮转？

你会记得 `cron` 通常被配置为运行 _/etc/cron.daily_ 中的脚本——所以看看那里，你应该会看到一个叫 `logrotate` 的脚本——也可能叫 _00logrotate_，强制让它成为第一个运行的任务。

## 配置 LOGROTATE

整体配置在 _/etc/logrotate.conf_ 中设置——看看那个文件，但也要看看 _/etc/logrotate.d_ 目录下的文件，因为它们是合并进来共同构成完整配置的。
你大概会看到一个叫 _apache2_ 的文件，内容像这样：

     /var/log/apache2/*.log {
     weekly
     missingok
     rotate 52
     compress
     delaycompress
     notifempty
     create 640 root adm
     }

其中大部分都相当清楚：任何 apache2 的 .log 文件都会每周轮转一次，保留 52 份压缩副本。

通常当你安装一个应用时，会同时为你安装一份合适的 logrotate“配方”，所以一般你不会从零开始创建它们。不过，默认设置并不总是符合你的需求，所以作为系统管理员去编辑它们是完全合理的——例如，上面这个默认的 _apache2_ 配方会生成 52 份每周日志，但你可能会发现把日志改成每天轮转、自动把一份副本邮件发给审计员、并且只在服务器上保留 30 天份的日志更有用。
