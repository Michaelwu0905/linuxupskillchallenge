## 简介

你的服务器现在运行的两个服务是用于远程登录的 *sshd* 和用于 Web 访问的 *apache2*。它们都通过 TCP/IP 的“端口”对世界开放——分别是 22 和 80。

作为系统管理员，你需要了解你的服务器上开放了哪些端口，因为每一个开放的端口也都是潜在的攻击焦点。你需要有能力部署合适的监控和管控措施。

## 说明

首先我们来看看确定服务器上开放了哪些端口的几种方法：

* `ss`——“socket status”（套接字状态），是一个标准工具——替代了更老的 `netstat`
* `nmap`——这个“端口扫描器”通常不会默认安装

`ss` 有大量可用的选项，但先试试：*ss -ltpn*

输出的各行显示了哪些端口在哪些接口上开放：

    sudo ss -ltp
    State   Recv-Q  Send-Q   Local Address:Port     Peer Address:Port  Process
    LISTEN  0       4096     127.0.0.53%lo:53        0.0.0.0:*      users:(("systemd-resolve",pid=364,fd=13))
    LISTEN  0       128            0.0.0.0:22           0.0.0.0:*      users:(("sshd",pid=625,fd=3))
    LISTEN  0       128               [::]:22              [::]:*      users:(("sshd",pid=625,fd=4))
    LISTEN  0       511                  *:80                *:*      users:(("apache2",pid=106630,fd=4),("apache2",pid=106629,fd=4),("apache2",pid=106627,fd=4))

网络表示法可能有点让人困惑，但上面这些行显示 80 和 22 端口在所有本地 IP 地址上“对世界”开放——而 53 端口（DNS）只在某个特殊的本地地址上开放。

现在用 `apt install` 安装 `nmap`。它的工作方式很不一样，会主动探测 1000 个甚至更多端口来检查它们是否开放。它最出名的是用来扫描远程机器——请不要这么做——但用它扫描你自己的服务器来检查自己的配置也非常方便：

    $ nmap localhost

    Starting Nmap 5.21 ( http://nmap.org ) at 2013-03-17 02:18 UTC
    Nmap scan report for localhost (127.0.0.1)
    Host is up (0.00042s latency).
    Not shown: 998 closed ports
    PORT   STATE SERVICE
    22/tcp open  ssh
    80/tcp open  http

    Nmap done: 1 IP address (1 host up) scanned in 0.08 seconds

22 端口提供 *ssh* 服务，也就是你当前连接所用的服务，所以它当然是开放的。如果你在运行 Apache，那么 80/http 端口也会开放。每一个开放的端口都会增大“攻击面”，所以最佳实践是关掉你不需要的服务。

不过要注意，“localhost”（127.0.0.1）是回环网络设备。_仅_“绑定”到它的服务只在这台本机上可用。要看你实际上向别人暴露了什么，先用 `ip a` 命令找到你真实网卡的 IP 地址，然后对那个地址跑 `nmap`。

## 主机防火墙

Linux 内核有名为 “netfilter” 的内置防火墙功能。我们通过各种工具来配置和查询它，其中最低层的是 `iptables` 命令，以及更新的 `nftables`。它们很强大，但也很复杂——所以我们要用一个更友好的替代品——`ufw`，也就是 “uncomplicated firewall”（不复杂防火墙）。

首先，通过输入 `sudo iptables -L` 列出当前有哪些规则。

你会看到类似这样的内容：

    Chain INPUT (policy ACCEPT)
    target  prot opt source             destination

    Chain FORWARD (policy ACCEPT)
    target  prot opt source             destination

    Chain OUTPUT (policy ACCEPT)
    target  prot opt source             destination

所以本质上没有任何防火墙——任何流量都被接受到任何地方。

使用 `ufw` 非常简单。8.04 LTS 之后的所有 Ubuntu 安装中都默认带有它，但如果你需要安装：

    sudo apt install ufw

然后，要允许 SSH 但禁止 HTTP，我们会输入：

    sudo ufw allow ssh
    sudo ufw deny http

**当心！** 别忘了显式地 ALLOW（允许）`ssh`，否则你将与服务器失去一切联系！如果不允许，防火墙默认会认为该端口是被 DENIED（拒绝）的。

然后用下面命令启用它：

    sudo ufw enable

现在输入 `sudo iptables -L` 会列出由此生成的详细规则——其中一条应该是：

    “DROP       tcp  --  anywhere             anywhere             tcp dpt:http”

这样做的效果是：虽然你的服务器仍在运行 Apache，但它已经无法从“外部”访问了——所有发往 http/80 目标端口的入站流量都会被 DROP（丢弃）。自己试试看！你大概会想用下面的命令把它改回来：

    sudo ufw allow http
    sudo ufw enable

在实践中，确保不运行不必要的服务通常就足够起到保护作用，基于主机的防火墙并非必需，但这在很大程度上取决于你配置的服务器类型。无论如何，希望这节课让你对这些概念有所领悟。

顺便说一句：对于这台测试/学习服务器，你现在应该再次允许 http/80 访问，因为那些 `access.log` 文件会让你真切体会到一个在充满敌意的世界中运行的服务器是什么样的。

## 使用非标准端口

偶尔，把某个服务重新配置成在非标准端口上提供是合理的——这对 **ssh/22** 是特别常见的建议——做法是修改 `/etc/ssh/sshd_config` 中的配置。

有人把这称为“隐晦式安全（security by obscurity）”——相当于把你前门上的锁孔挪到一个不寻常的位置，而不是改进锁本身；或者给你的坦克做伪装，而不是改进它的装甲——但它确实能有效消除机会主义黑客的攻击，而这对大多数服务器来说正是主要威胁。

不过，如果你要这么做，请记住你已经部署的所有规则和安全工具。例如，如果你用的是 AWS，并且把 SSH 端口改成 2222，你就需要在实例的 EC2 安全组中开放那个端口。
