## 简介

之前你已经用 `apt install` 给服务器安装了一些软件包。那相当轻松，我们也解释了 Linux 的软件安装模式与 Android、iPhone 上的“应用商店”有多相似，而 MacOS 和 Windows 也在越来越向这个方向靠拢。

不过今天，你要“掀起盖子”看看它是如何工作的；更好地理解它的优势（以及劣势！）——并且看看你如何能安全地把这套体系扩展到主要的官方源之外。

## 今天的任务

* 添加一个新的仓库
* 移除一个仓库
* 弄清从哪里获取某个程序（apt search）
* 不用 apt 安装一个程序

## 仓库与版本

任何特定的 Linux 安装都有若干重要特征：

* 版本——例如 Ubuntu 20.04、CentOS 5、RHEL 6
* “位宽”——32 位或 64 位
* 芯片——Intel、AMD、PowerPC、ARM

版本号尤其重要，因为它决定了你能安装的应用版本。Ubuntu 18.04 发布时（2018 年 4 月——版本号就是这么来的！），它自带的是 Apache 2.4.29。所以，如果你的服务器运行 18.04，那么即使你在五年之后用 `apt` 安装 Apache，你拿到的仍然还是那个版本。这带来了稳定性，但对那些渴望后续版本某项功能的网页设计者来说，代价是显而易见的。安全补丁*确实*会被做进仓库，但方式是把后续版本的安全修复“向后移植（backport）”到最初发布的那个旧的稳定版本中。

## 这些配置都在哪里？

我们要讨论 Debian 和 Ubuntu 发行版（以及几十个衍生版）使用的“软件包管理器”。它使用 `apt` 命令，但在大多数用途上，Red Hat 家族（如 RHEL、Fedora、RockyLinux 和 CentOS）使用的竞争对手 `yum` 和 `dnf` 命令的工作方式非常相似——其他版本的同类工具也是如此。

配置是通过 _/etc/apt_ 目录下的文件完成的。要看你安装的软件包来自哪里，用 `less` 查看 _/etc/apt/sources.list.d/ubuntu.sources_，你会看到为你的具体版本指定仓库 URI、套件（suite）和组件（component）的条目：

```bash
     Types: deb
     URIs: http://archive.ubuntu.com/ubuntu/
     Suites: noble noble-updates noble-backports
     Components: main restricted universe multiverse
```
Debian 和其他基于 Debian 的发行版仍然直接在 _/etc/apt/sources.list_ 中以单行形式配置它，但参数是一样的：

* 软件包类型：`deb`
* URI（源）：最常见的是用来拉取软件包的网址
* Suite（套件）：该发行版版本的代号，也就是 Ubuntu 24.04 叫 Noble，26.04 叫 Jammy，以此类推。
* Components（组件，即实际的仓库）：你要从它那里拉取哪一组软件包，“main” 还是某些额外的

一条 `sources.list` 行的例子：为 Debian 13（trixie）从 `main` 和 `non-free-firmware` 仓库拉取 `deb` 软件包：

```bash
deb http://deb.debian.org/debian trixie main non-free-firmware
```

现在没必要纠结它的确切语法，但相当常见的情况是你想添加额外的仓库——这就是我们接下来要处理的。

## 额外的仓库

主仓库包含操作系统运行所需的核心、必需软件包，包括内核、基础工具和关键库。虽然这些仓库里有数量惊人的软件可用，但经常有一些软件包因为被视为_非必需_而不可用。它们通常会按下面的标准被划分到不同的仓库中：

* 稳定性：当新软件包刚引入时，`unstable` 仓库可以充当滚动发布流，而官方支持则更侧重于 `main` 这样的 `stable` 仓库——那里的软件包在 bug 和冲突方面经过了充分测试。
* 理念：该软件能否以自由许可提供（[自由如自由，而非免费如啤酒](https://www.debian.org/intro/free)）；专有应用和非自由固件通常会被推到单独的仓库中。

所以接下来，你要给系统添加一个额外的仓库，并从中安装软件。

## 启用额外的仓库

先快速检查一下你*本来*就已经可以安装多少个软件包。要获取完整列表和细节，可以运行：

`apt-cache dump`

……但你得按几次 Ctrl-c 才能停下它，因为它实在太啰嗦了。

换个办法，用 `grep` 只过滤出软件包名，然后用 `wc -l` 数一下（`wc` 是 “word count”，`-l` 让它统计行数而不是单词数）——像这样：

`apt-cache dump | grep "Package:" | wc -l`

这些就是你现在能安装的所有软件包。有时候，如果你启用额外的仓库，还会有更多软件包可用。大多数 Linux 发行版都有类似的概念，但在 Ubuntu 中，“Universe” 和 “Multiverse” 仓库常常默认被禁用。它们由 Ubuntu 托管，但支持较少，而 Multiverse：“包含被归类为非自由的软件……可能不包含安全更新”。Multiverse 里有用的工具例子可能包括压缩工具 `rar` 和 `lha`，以及网络性能测试工具 `netperf`。

要启用 “Multiverse” 仓库，你可以参照 [Ubuntu 社区指南](https://help.ubuntu.com/community/Repositories/CommandLine)，但基本上你只需在你的 apt 源文件中_为那个仓库添加一条登记项_。

添加之后，更新你本地可用应用的缓存：

`sudo apt update`

完成后，例如用 `apt-cache search netperf` 搜索你要找的应用，而不是手动运行那个 dump 列表。你会看到一个更短的列表，包含相关软件包的名称和一行简短描述。

然后像这样查看 `netperf`：

`apt-cache policy netperf`

……输出会显示它来自 Multiverse。

```bash
netperf:
  Installed: (none)
  Candidate: 2.7.0-0.1
  Version table:
     2.7.0-0.1 500
        500 http://mirrors.digitalocean.com/ubuntu noble/multiverse amd64 Packages
```

## 添加其他仓库

软件仍然可以以 `deb` 包格式提供，却不在任何官方源中，也就是说不来自 Debian 或 Ubuntu 的服务器。在这些情况下，有两种可能：

* 只提供了 `deb` 包，你必须用 `dpkg` 手动安装它（见下文）
* 开发公司提供了仓库源及其 [GPG 签名密钥](https://askubuntu.com/a/179237)，这样你就可以添加这样一条登记项：

```bash
Types: deb
URIs: https://brave-browser-apt-release.s3.brave.com
Suites: stable
Components: main
Architectures: amd64 arm64
Signed-By: /usr/share/keyrings/brave-browser-archive-keyring.gpg
```

通常你会有关于如何下载和验证 GPG 签名的说明（或者干脆有一个替你完成的脚本）。同样，请运用常识，只从可靠的来源下载。

另外提一句，[PPA](https://askubuntu.com/questions/4983/what-are-ppas-and-how-do-i-use-them)（Personal Package Archives，个人软件包归档）曾经是获取那些没能进入官方仓库的额外软件包的替代方式，但随着 Snap 和 Flatpak 这类现代应用商店被广泛采用，它已经过时了。

## APT 与 DPKG

那么你下载了一个 `.deb` 文件，想安装它。我可以用 `apt` 来处理吗？

嗯，[可以](https://unix.stackexchange.com/a/159114)。

`apt`（Advanced Package Tool）是解决依赖关系的高级软件包管理器，而 `dpkg`（Debian Package）是直接处理 `.deb` 文件的低级工具。

所以，你可以用这两种方式中的任意一种手动安装一个 `deb` 包：

```bash
dpkg -i /path/to/package/name.deb
apt install /path/to/package/name.deb
```

## DEBIAN/UBUNTU 生态之外的软件包

但如果我想用的应用没有 Debian/Ubuntu 版本呢？

你还有机会！看看那个应用是否在 **Snap** 或 **Flatpak** 中可用。这些格式是通用且跨发行版的，每个软件包都自带依赖。你得安装 Snap 才能从 [Snap Store](https://snapcraft.io/store) 下载（中心化，由 Canonical 开发），或者安装 Flatpak 以从 [FlatHub](https://flathub.org/) 这类地方拉取软件包（去中心化，社区维护的生态）。

无论如何，如果你安装的软件是开源的，你多半还可以选择[从源码安装](./17.md)。

免责声明：能的话就使用原生软件包或从源码构建。应用商店里那些自带依赖的应用往往会产生性能和资源开销。

## 小结

只从默认仓库安装显然是最安全的，但常常有充分的理由要走出它们。作为系统管理员，你需要判断风险，并评估某个应用是否值得使用不同的软件包管理方案。

一般规则是：

* 接入超过一两个额外仓库要有充分的理由；更多并不一定更好。
* 先用点时间了解一下某个仓库，理解它可能存在的缺点。
