## 简介

今天我们要看看如何快速高效地查找文件，以及文件中的文本。

知道某个文件或设置存在，却找不到它，这非常令人沮丧！掌握今天的命令之后，你管理系统时会自信得多。

今天你会看到一些有用的工具：

* `locate`
* `find`
* `grep`
* `which`

## 今天的任务

* 找出所有内容中包含单词 “Permission” 的文件

## 说明

### _locate_

如果你要找的是一个叫 `access.log` 的文件，那么最快的方法是用 “locate”，像这样：

	$ locate access.log
	/var/log/apache2/access.log
	/var/log/apache2/access.log.1
	/var/log/apache2/access.log.2.gz

（如果 `locate` 没有安装，用 `sudo apt install plocate` 安装它）

如你所见，默认情况下它把对 *“某物”* 的搜索当作对 *“\*某物\*”* 的搜索。它非常快，因为搜索的是一个索引，但如果这个索引过期或缺失，它可能给不出你要找的答案。这是因为索引是由 `updatedb` 命令创建的——通常只由 `cron` 每晚运行一次。因此对于最近新增的文件，它可能已经过期，所以手动运行 `sudo updatedb` 更新索引是值得的。

### _find_

`find` 命令会沿着目录结构向下搜索符合条件的文件——条件可以是名称，也可以是大小，或者最后更新时间等等。试试这些例子：

	find /var -name access.log
	find /home -mtime -3

第一条搜索名为 “access.log” 的文件，第二条搜索 `/home` 下最后修改日期在最近 3 天内的任何文件。

这些会比 `locate` 花更长时间，因为它们直接搜索文件系统，而不是从索引中查。另外，由于 `find` 使用已登录用户的权限，如果你搜索整个系统，很多目录会给你 “permission denied”（权限不足）的消息。当然，用 `sudo` 开头会以 *root* 身份运行它——或者你可以用 `grep` 过滤掉这些错误，像这样：`find /var -name access.log 2>&1 | grep -vi "Permission denied"`。

这些例子只是巨大冰山的一角，看看“资源”部分中的文章，尽可能多做些练习——花时间真正把 `find` 用熟练是不会白费的。

### _grep -R_

与其让 “grep” 在某个特定文件里搜索文本，你可以给它整个目录结构，让它递归地向下搜索，包括跟随所有符号链接（`-r` 不会跟随符号链接）。
当你“就是知道”某个条目出现在“某个地方”但不确定是哪里时，这个技巧特别方便。

举个例子，你知道 “PermitRootLogin” 是 /etc 下某个配置文件中的 ssh 参数，但想不起来它到底保存在哪里：

 `grep -R -i "PermitRootLogin" /etc/*`

由于它只对纯文本文件有效，所以对 `/etc` 和 `/var/log` 文件夹最有用。（注意 `-i` 让搜索“不区分大小写”，即使这个设置被写成 “Permitrootlogin” 也能找到。）

你现在可能有像 `/var/log/access.log.2.gz` 这样的日志——这些是被压缩以节省磁盘空间的旧日志——所以你无法用 `less` 读取它们，也无法用 `grep` 搜索它们。不过，有 `zless` 和 `zgrep`，它们可以正常工作，而且对普通文件和压缩文件都适用。

### _which_

有时候知道一条命令是从哪里运行的很有用。如果你输入 `nano`，它启动了，那么这个 `nano` 二进制文件是从哪儿来的？一般规则是，系统会搜索你 “path” 中设置的那些位置。要查看它，输入：

`echo $PATH`

要看 `nano` 从哪儿来，输入：

`which nano`

对 `grep`、`vi`、`service` 和 `reboot` 也试试。你会注意到它们通常总是位于名为 `bin` 的子文件夹里，但有好几个不同的这种文件夹。

## 扩展

`find` 命令的 `-exec` 功能极其强大。

但“查找东西”远不止于此！你不仅可以追踪文件的内容，还可以用 `lsof` 和 `fuser` 之类的命令追踪它的**使用情况**。
