## 简介

Linux 有一套丰富的功能用来运行计划任务。优秀系统管理员的一个关键特质就是让计算机替你干活（有时会被误解成懒惰！）——而一套配置良好的计划任务是让服务器保持良好运行的关键。

基于时间的任务调度器 [cron(8)](https://linux.die.net/man/8/cron) 是 Linux 系统管理员最常用的一个。它大致从 Unix System V 时代起就以现在这种形式存在，并使用了被广泛采用的标准化语法。

### 用 at 调度一次性任务

如果你用的是 Ubuntu，可能首先需要安装 _at_ 软件包。

```bash
sudo apt update
sudo apt install at
```

我们会用 `at` 命令来安排一个在未来某个时间点运行的_一次性_任务。

接下来，让我们打印连接到标准输入的终端文件名（在 Linux 中一切皆文件，包括你的终端！）。我们要在未来某个时间点向终端 echo 一些东西，以便理解用 _at_ 调度未来任务是怎么回事。

```bash
vagrant@ubuntu2204:~$ tty
/dev/pts/0
```

现在我们安排一条命令，在 1 分钟后向我们的终端 echo 一句问候。

```bash
vagrant@ubuntu2204:~$ echo 'echo "Greetings $USER!" > /dev/pts/0' | at now + 1 minutes
warning: commands will be executed using /bin/sh
job 2 at Sun May 26 06:30:00 2024
```

几秒钟后，我们的终端上应该会打印出一句问候。

```bash
...
vagrant@ubuntu2204:~$ Greetings vagrant!
```

用它来安排一次性任务并不算常见，但如果你真的有需要，现在你已经对它可以怎么用有了概念。下一节我们会学习如何用 cron 和 crontab 安排基于时间的任务。

_想更深入地探索用 `at` 安排任务，请参阅下面[延伸阅读](#延伸阅读)部分的相关文章。_

### 用 crontab 调度作业

在 Linux 中，我们用 `crontab` 命令与由 cron 守护进程调度的任务交互。每个用户（包括 root 用户）都可以调度以自己用户身份运行的作业。

用 `crontab -l` 显示你的用户的 crontab。

```bash
vagrant@ubuntu2204:~$ crontab -l
no crontab for vagrant
```

除非你已经为你的用户创建过 crontab，否则你大概还没有。我们创建一个简单的 cron 作业来理解它是如何工作的。

用 `crontab -e` 命令创建我们的第一个 cron 作业。在 Ubuntu 上，如果这是你第一次编辑 crontab，会看到一个菜单让你选择首选的编辑器。

```bash
vagrant@ubuntu2204:~$ crontab -e
no crontab for vagrant - using an empty one

Select an editor.  To change later, run 'select-editor'.
  1. /bin/nano        <---- easiest
  2. /usr/bin/vim.basic
  3. /usr/bin/vim.tiny
  4. /bin/ed

Choose 1-4 [1]: 2
```

选择你喜欢的编辑器，然后按 _Enter_。

在文件底部添加下面这个 cron 作业，然后保存并退出文件。

```bash
* * * * * echo "Hello world!" > /dev/pts/0
```

> 注意：确保 `/dev/pts/0` 这个文件路径与[上面](#用-at-调度一次性任务)你的 `tty` 命令打印出来的内容一致。

接下来，再次运行 `crontab -l`，看看我们刚安装的 crontab。你应该会看到自己创建的 cron 作业打印到了终端上。

```bash
vagrant@ubuntu2204:~$ crontab -l
* * * * * echo "Hello world!" > /dev/pts/0
```

这个 cron 作业会每分钟向你的终端打印字符串 `Hello world!`，直到我们移除或更新这个 cron 作业。等上几分钟看看它会做什么。

```bash
vagrant@ubuntu2204:~$ Hello world!
Hello world!
Hello world!
...
```

准备好了就用 `crontab -r` 卸载你创建的 crontab。

### 理解 crontab 语法

基本的 crontab 语法如下：

```
* * * * * command to be executed
- - - - -
| | | | |
| | | | ----- Day of week (0 - 7) (Sunday=0 or 7)
| | | ------- Month (1 - 12)
| | --------- Day of month (1 - 31)
| ----------- Hour (0 - 23)
------------- Minute (0 - 59)
```

* 分钟值可以是 0 到 59。
* 小时值可以是 0 到 23。
* 月内日期值可以是 1 到 31。
* 月份值可以是 1 到 12。
* 星期值可以是 0 到 6，其中 0 表示星期日。

还有一些不同的操作符可以作为简写，用来在每个字段中指定多个值：

| 符号 | 说明                                                |
|--------|------------------------------------------------------------|
| *      | 通配符，指定所有可能的时间间隔           |
| ,      | 用逗号分隔来列出多个值。                 |
| -      | 用连字符分隔来指定两个数字之间的范围 |
| /      | 用斜杠来指定周期/频率              |

还有一个很好用的网站可以检查 cron 表达式：[crontab.guru](https://crontab.guru/)。

_用 crontab.guru 网站试着玩不同的表达式，找找它是如何工作的感觉，或者点击 **random** 按钮随机生成一个表达式。_

## 今天的任务

1. 调度用户主目录的每日备份
2. 调度一个任务，查找所有超过 7 天的备份并删除它们

### 自动化常见的系统管理任务

cron 作业一个常见的用途就是调度各种备份。作为 root 用户，我们要创建一个 cron 作业，用 `tar` 工具为所有用户的主目录创建压缩归档。Tar 是 “tape archive”（磁带归档）的缩写，可以追溯到 Unix 和 Linux 的早期，那时数据通常被归档到类似盒式磁带的磁带存储上。

一般来说，把命令或脚本安装成 cron 作业之前先测试一下是好的做法。首先我们手动运行一次 `tar` 命令的某个版本，为 `/home` 创建备份。

```bash
vagrant@ubuntu2204:~$ sudo tar -czvf /var/backups/home.tar.gz /home/
tar: Removing leading `/' from member names
/home/
/home/ubuntu/
/home/ubuntu/.profile
/home/ubuntu/.bash_logout
/home/ubuntu/.bashrc
/home/ubuntu/.ssh/
/home/ubuntu/.ssh/authorized_keys
...
```

> 注意：我们给 `tar` 传了 `-v`（verbose，详细）标志，这样能更好地看到它在做什么。`-czf` 依次代表 “create”（创建）、“gzip compress”（gzip 压缩）和 “file”（文件）。更多细节见 `man tar`。

我们再用 `date` 命令，把备份的日期插入文件名中。由于我们会每天备份，这个 cron 作业跑几天之后，我们就会有几天份的备份，每个归档都_标记_着各自的日期。

```bash
vagrant@ubuntu2204:~$ date
Sun May 26 04:12:13 UTC 2024
```

`date` 命令默认打印的字符串不太有用。我们把日期输出成 ISO 8601 格式，有时也称为“ISO 日期”。

```bash
vagrant@ubuntu2204:~$ date -I
2024-05-26
```

这是个更有用的字符串，我们可以把它和 `tar` 命令结合起来，创建一个文件名里包含今天日期的归档。

```bash
vagrant@ubuntu2204:~$ sudo tar -czvf /var/backups/home.$(date -I).tar.gz /home/
tar: Removing leading `/' from member names
/home/
/home/ubuntu/
...
```

我们来看看创建出来的备份，理解一下这个 date 命令是如何被插入到文件名里的。

```bash
vagrant@ubuntu2204:~$ ls -l /var/backups
total 16
-rw-r--r-- 1 root root 8205 May 26 04:16 home.2024-05-26.tar.gz
-rw-r--r-- 1 root root 3873 May 26 04:07 home.tar.gz
```

> 注意：这些 `.tar.gz` 文件常被系统管理员称为 [tarballs](https://wiki.debian.org/TarBall)。

用 `sudo crontab -e` 创建并编辑 root 的 crontab，添加下面这个 cron 作业。

```bash
0 5 * * * tar -zcf /var/backups/home.$(date -I).tar.gz /home/
```

这个 cron 作业会在每天 05:00 运行。几天之后，`/var/backups` 里就会有若干份用户主目录的备份。

如果我们让这个 cron 作业无限期地跑下去，过一段时间 `/var/backups` 里就会堆积大量备份。随着时间推移，占用的磁盘空间会不断增长，最终可能把磁盘填满。最好别让这件事发生。为了降低这个风险，我们会再设置一个每天运行的 cron 作业，清理掉那些我们不需要保留的旧备份。

`find` 命令就像一把瑞士军刀，可以按各种条件查找文件并列出它们，或者对它们做其他事情，比如删除。我们要精心构造一条 `find` 命令，找出我们创建的所有备份，并删除任何超过 7 天的备份。

首先我们通过查找并列出所有备份来理解 `find` 命令是怎么工作的。

```bash
vagrant@ubuntu2204:~$ sudo find /var/backups -name "home.*.tar.gz"
/var/backups/home.2024-05-26.tar.gz
...
```

这条命令做的是：在 `/var/backups` 中查找所有以 `home.` 开头、以 `.tar.gz` 结尾的文件。`*` 是一个匹配任意字符串的通配符。

在我们的场景中，需要创建一个计划任务，找出 `/var/backups` 中所有超过 7 天的文件并删除它们。运行 `sudo crontab -e` 并安装下面这个 cron 作业。

```bash
30 5 * * * find /var/backups -name "home.*.tar.gz" -mtime +7 -delete
```

> 注意：`-mtime` 标志是 “modified time”（修改时间）的缩写，在我们的场景中，`find` 会查找 _修改_ 时间在 7 天以上的文件，这就是 _+7_ 的含义。`find` 命令会在[第 11 天 - 查找东西……](11.md)中更详细地讲解。

到现在，我们的 crontab 应该差不多是这样的：

```bash
vagrant@ubuntu2204:~$ sudo crontab -l
# Daily user dirs backup
0 5 * * * tar -zcf /var/backups/home.$(date -I).tar.gz /home/
# Retain 7 days of homedir backups
30 5 * * * find /var/backups -name "home.*.tar.gz" -mtime +7 -delete
```

用 `find ... -delete` 语法来设置 cron 作业，是系统管理员管理文件、删除不再需要的旧文件以防磁盘被填满时相当惯用的做法。经常可以看到更复杂的 _cron 脚本_，它们组合使用 `tar`、`find` 和 `rsync` 之类的工具，以增量方式或按计划管理备份，并基于真实场景实施更精细的保留策略。

## 系统 crontab

在 `/etc/crontab` 中还定义了一个系统范围的 crontab。我们来看看这个文件。

```bash
vagrant@ubuntu2204:~$ cat /etc/crontab
# /etc/crontab: system-wide crontab
# Unlike any other crontab you don't have to run the `crontab'
# command to install the new version when you edit this file
# and files in /etc/cron.d. These files also have username fields,
# that none of the other crontabs do.

SHELL=/bin/sh
# You can also override PATH, but by default, newer versions inherit it from the environment
#PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * user-name command to be executed
17  *  *  *  *  root      cd / && run-parts --report /etc/cron.hourly
25  6  *  *  *  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.daily )
47  6  *  *  7  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.weekly )
52  6  1  *  *  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.monthly )
```

到现在，基本语法对你来说应该很熟悉了，但你会注意到多了一个字段 _user-name_。它指定运行该任务的用户，是 `/etc/crontab` 这个系统 crontab 独有的。

系统管理员如今已不常使用 `/etc/crontab`，而是鼓励用户为自己的用户安装自己的 crontab，即使是 root 用户也是如此。用户 crontab 都位于 `/var/spool/cron` 中。具体子目录往往因发行版而异。

```bash
vagrant@ubuntu2204:~$ sudo ls -l /var/spool/cron/crontabs
total 8
-rw------- 1 root    crontab  392 May 26 04:45 root
-rw------- 1 vagrant crontab 1108 May 26 05:45 vagrant
```

每个用户都有自己的 crontab，文件名就是他们的用户名。

注意上面显示的系统 crontab 还管理着以脚本形式存在于 `/etc/cron.*` 目录中、按_每天_、_每周_和_每月_运行的 cron 作业。我们看一个例子。

```bash
vagrant@ubuntu2204:~$ ls -l /etc/cron.daily
total 20
-rwxr-xr-x 1 root root  376 Nov 11  2019 apport
-rwxr-xr-x 1 root root 1478 Apr  8  2022 apt-compat
-rwxr-xr-x 1 root root  123 Dec  5  2021 dpkg
-rwxr-xr-x 1 root root  377 Jan 24  2022 logrotate
-rwxr-xr-x 1 root root 1330 Mar 17  2022 man-db
```

这些文件每一个都是一个脚本，或者是指向某个脚本的快捷方式，用来做一些常规任务，它们由 `run-parts` 按字母顺序运行。所以在这个例子中，_apport_ 会最先运行。用 `less` 或 `cat` 查看你系统上的一些脚本——很多看起来会非常复杂，最好别去动它们；但另一些可能只是几行简单的命令。

```bash
vagrant@ubuntu2204:~$ cat /etc/cron.daily/dpkg
#!/bin/sh

# Skip if systemd is running.
if [ -d /run/systemd/system ]; then
  exit 0
fi

/usr/libexec/dpkg/dpkg-db-backup
```

除了用 `crontab` 调度作业之外，你也可以创建一个脚本放进 `/etc/cron.{daily,weekly,monthly}` 中的某个目录，它就会按期望的间隔被运行。

## 关于 systemd 定时器的一点说明

现在所有主流 Linux 发行版都包含 “systemd”。除了启动和停止服务之外，它_也_可以通过“定时器（timers）”在特定时间运行任务。用下面命令看看你的服务器上已经配置了哪些：

```bash
systemctl list-timers
```
