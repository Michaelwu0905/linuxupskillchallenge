# Day 17 - 从源码构建

* [课程视频](https://youtu.be/a9_hry-8Hhw)
* 配套视频：[从源码安装与配置](https://www.youtube.com/live/5oGwnrd44BI?t=8126s)

## 简介

几天前我们看到了如何授权额外的仓库，让 `apt-cache` 在我们需要不常见的应用、或者比标准仓库里更新的版本时可以去搜索。

今天我们要更进一步——字面意义上的“回到源头（go to the source）”。这不是可以轻率去做的事——软件包管理器存在的全部意义就是让你的生活更轻松——但偶尔它是有正当理由的，而且这是你需要了解并能够从容应对的事情。

到目前为止我们安装的应用都来自仓库。那里的文件是“二进制文件”——预先编译好的，而且常常被你的发行版做了定制。可能不太清楚的是，你的发行版是从各种互不协调的开发项目（即“上游”）获取这些应用的，而这些开发者一直在开发新版本。我们会去其中一个项目，下载源码，编译并安装它。

（像 `apt` 这样的软件包管理器所做的另一大工作，就是找出并安装任何所需的“依赖”。在 Linux 世界里，许多开源应用都以这种方式利用已有的基础设施，但手动解决依赖会非常棘手。不过，我们今天要从源码安装的这个应用比较特殊，它是完全独立的。）

## 今天的任务

* 下载一个源代码 tarball
* 解包并构建源码

## 首先我们需要必需品

项目通常以“源文件”的形式提供它们的应用，用 C、C++ 或其他计算机语言编写。我们准备拉取这样一个源文件，但在把它编译成“可执行文件”——一个我们服务器能运行的程序——之前，它对我们是没用的。所以，我们需要先安装一套常见的编译器和类似工具。在 Ubuntu 上，这类工具的软件包叫 “build-essential”。像这样安装它：

`sudo apt install build-essential`

## 获取源码

首先，测试一下你是否已经装好了 `nmap`，并输入 `nmap -V` 看看你用的是哪个版本。这是从你的标准仓库安装的版本。接下来，输入：`which nmap`——看看这个可执行文件存放在哪里。

现在我们去开发者项目的“项目页面” _http://nmap.org/_，抓取最新的前沿版本。找到下载页面，然后是 “Source Code Distribution” 部分，以及 “Latest development nmap release tarball” 的链接，记下它的 URL——大概是这样的：

     https://nmap.org/dist/nmap-7.70.tar.bz2

这是 7.70 版，也就是这些笔记写作时的最新开发版本，但现在可能已经不同了。那么现在我们把它拉到你的服务器上。第一个问题是放在哪里——我们放到你的主目录里，所以先切换到主目录：

`cd`

然后直接用 `wget`（“web get”）像这样下载文件：

`wget -v https://nmap.org/dist/nmap-7.70.tar.bz2`

`-v`（verbose，详细）会给出一些反馈，让你看到正在发生什么。下载完成后，列一下目录内容检查：

`ls -ltr`

正如我们学过的，文件名的结尾通常是文件格式的线索——在这个例子中 “.bz2” 表示它是一个用 bz2 算法压缩的 tarball。虽然我们可以分两步先解压缩、再合并文件，但也可以用一条命令完成——像这样：

`tar -j -x -v -f   nmap-7.70.tar.bz2`

……其中 -j 表示“先解压 bz2 文件”，-x 是提取，-v 是详细输出——而 -f 表示“文件名紧随其后”。通常我们实际上会更简洁地写成：

`tar -jxvf  nmap-7.70.tar.bz2`

那么，让我们看看结果，

`ls -ltr`

记住目录在列表中有个开头的 “d”，你会看到创建了一个目录：

     -rw-r--r--  1 steve  steve  21633731    2011-10-01 06:46 nmap-7.70.tar.bz2
     drwxr-xr-x 20 steve  steve  4096        2011-10-01 06:06 nmap-7.70

现在用 `mc` 或直接 `cd nmap-7.70` 探索它的内容——你应该能用 `ls` 和 `less` 找到并读取真正的源代码。即使你完全不懂编程，那些注释读起来也可能挺有意思。

按惯例，源码文件的根目录里通常会有一些大写名称的文本文件，例如：README 和 INSTALLATION。找到它们，用 `more` 或 `less` 读一读。重要的是要意识到，“上游”项目的程序员并不是为 Ubuntu、CentOS——甚至不是为 Linux 写的。他们用 C 或 C++ 等写了一个正确的、能工作的程序并把它提供出来，但如何把它针对我们的操作系统、芯片类型等编译出来，就得我们自己想办法。（希望这能让你稍微体会到 CentOS、Ubuntu 这类发行版以及 `apt`、`yum` 这类工具所增加的价值，以及从零构建你自己的 Linux From Scratch 会有多难。）

那么，在这个例子里我们看到的 INSTALL 文件写着类似这样简短的话：

     Ideally, you should be able to just type:

     ./configure
     make
     make install

     For far more in-depth compilation, installation, and removal notes
     read the Nmap Install Guide at http://nmap.org/install/ .

事实上，这对许多软件包来说都相当标准。下面是每一步做的事情：

* `./configure`——这是一个脚本，用来检查你的服务器（比如看它是基于 ARM 还是 Intel、32 位还是 64 位、你有哪些编译器等等）。也可以给它传参数来定制软件的编译，例如不包含任何在 GUI 环境中运行的额外支持——这在“无头”（headless，即远程纯文本服务器）上很有意义；或者以牺牲速度为代价优化到最低内存占用——如果你的服务器 RAM 很少，这可能也有意义。如果它问了任何问题，就采用默认值——如果看到一些 WARNING 消息也别慌，很可能一切都会顺利。
* `make`——编译软件，通常会调用 GNU 编译器 `gcc`。这可能会产生大量看着吓人的文本，并花上一两分钟——对于像 LibreOffice 这样非常大的软件包，甚至可能花上一两个小时。
* `make install`——这一步会把你编译好的文件以及文档安装到你的系统上，某些情况下还会设置服务和计划任务等等。到现在为止你一直只在你的主目录里操作，但这一步会为所有用户安装到系统上，所以需要 `root` 权限。因此，你实际上需要运行：`sudo make install`。如果它问了任何问题，就采用默认值。

现在，最后这一步有可能已经覆盖了你原有的 `nmap`，但更可能的是这个新的被安装到了另一个位置。

一般来说，_/bin_ 是操作系统关键部分所在，_/usr/bin_ 用于不那么关键的工具，而 _/usr/local/bin_ 用于你自己选择手动安装的软件。当你输入一条命令时，它会依次搜索 PATH 环境变量中给出的每个目录，并启动第一个匹配项。所以，如果 _/bin/nmap_ 存在，它会被运行而不是 _/usr/local/bin_——但如果你给出你想要那个版本的“完整路径”——比如 _/usr/local/bin/nmap_——它就会运行那个版本。

“locate” 命令可以非常快地搜索文件，但由于这些文件刚刚才被添加，我们需要手动更新文件索引：

`sudo updatedb`

然后搜索索引：

`locate bin/nmap`

这应该会同时找到你新旧两份 `nmap` 副本。

现在试着分别运行它们，例如：

`/usr/bin/nmap -V`

`/usr/local/bin/nmap -V`

`nmap` 工具不依赖任何其他软件包或库，所以从源码安装非常容易。其他大多数软件包都有很多“依赖”，因此即使有很好的说明，手动从源码安装也可能相当有挑战性（看看 <http://oss.oetiker.ch/smokeping/doc/smokeping_install.en.html>，那是个很好的例子）。

注意：因为你是在 `apt` 体系之外完成这一切的，所以当你运行 `apt update` 时这个二进制文件不会得到更新。对于 `nmap` 这样的工具来说大概不是什么大问题，但对于任何作为对外暴露的服务运行的东西来说，重要的是你要明白：你现在必须自己跟踪该应用（及其所有依赖）的安全公告，并在修复后的新版本可用时安装它们。对生产服务器来说，这是一个很大的麻烦/风险。
